# Финские Новости — бэкенд агрегатора

Реальный сервис, который тянет RSS из YLE, Helsingin Sanomat, Iltalehti и
Ilta-Sanomat и **пересказывает** заголовки и краткое содержание на русском
языке — не дословный перевод, а самостоятельная переформулировка сути через
Claude API, с обязательной ссылкой на оригинал у каждой новости.

## Быстрый старт

```bash
npm install
cp .env.example .env
# впишите в .env свой ANTHROPIC_API_KEY (см. ниже)
npm start
```

Сервер поднимется на `http://localhost:3000`. Первое обновление лент
запустится сразу при старте, дальше — каждые `REFRESH_INTERVAL_MINUTES` минут
(по умолчанию 15).

Проверить, что всё работает, без ожидания cron:
```bash
npm run refresh-once
```

## Как работает пересказ (src/aiRetell.js)

На вход модели идут только заголовок и краткое описание, которые сам сайт
уже публикует в открытом RSS-анонсе — не полный текст платной статьи.
Промпт явно требует от модели:
- не переводить дословно, а формулировать по-русски самостоятельно;
- не добавлять фактов, которых нет в оригинале;
- не копировать структуру и обороты речи исходного текста;
- уложиться в 2–3 предложения.

Статьи и результаты пересказа хранятся в SQLite (`DATABASE_PATH`, по
умолчанию `data/finskienovosti.db`). Уже сохранённые URL не пересказываются
повторно.

Перед миграцией или production-обновлением создайте согласованную резервную
копию:

```bash
npm run db:backup
```

Источник берётся из `DATABASE_PATH`, а каталог копий — из
`BACKUP_DIRECTORY` (по умолчанию `data/backups`). В Coolify каталог резервных
копий должен находиться на persistent volume или копироваться во внешнее
хранилище. Фундамент поэтапного мастер-плана и границы уже выполненного
описаны в [`docs/master-plan-audit.md`](docs/master-plan-audit.md).

Управляемые категории можно безопасно объединять в `/admin` во вкладке
«Справочники». Операция переносит статьи и фильтры подписок, скрывает прежнюю
категорию и сохраняет её старый URL как постоянное перенаправление. Сами
страницы статей и их slug не меняются.

Перед вызовом AI новые RSS-анонсы дополнительно сравниваются с материалами
других источников за тот же день. Совпадение пропускается только при высокой
уверенности по заголовку и краткому содержанию. Решение сохраняется в журнале
`article_duplicate_log` и видно редактору в `/admin`; уже опубликованный архив
никогда не удаляется этой проверкой.

## Расписание HSL в Telegram

Команда `/hsl` открывает поиск отправлений по номеру остановки. Бот также
принимает геопозицию и показывает ближайшие остановки, а номер на фотографии
таблички распознаёт через настроенный OpenAI API.

Для расписаний зарегистрируйтесь в официальном Digitransit API Portal,
подключите продукт Routing v2 HSL GTFS и добавьте ключ в Coolify:

```env
DIGITRANSIT_API_KEY=...
```

Ключ передаётся сервером в заголовке и не попадает в браузер или Telegram.

## Пересказ через OpenAI

Для экономичного пересказа используйте:

```env
RUSSIAN_PROVIDER=openai
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5-nano
```

Ключ создаётся в OpenAI Platform и хранится только как secret в Coolify.
`gpt-5-nano` выбран как наиболее дешёвая подходящая модель для коротких
пересказов. Если OpenAI сообщает об исчерпанной квоте или отсутствующем ключе,
админка получает системное уведомление, а новые статьи автоматически
переводятся аварийным бесплатным методом:

```env
RUSSIAN_FREE_FALLBACK=google
```

Для этого режима отдельный ключ не требуется. Используется публичный endpoint
Google Translate без SLA, поэтому это временная страховка, а не основной
провайдер. Он не включается при обычных сетевых сбоях OpenAI, чтобы временная
ошибка не приводила к неожиданной смене качества. Для контролируемого
production-резерва можно отдельно развернуть LibreTranslate:

```env
RUSSIAN_FALLBACK_PROVIDER=libretranslate
LIBRETRANSLATE_URL=http://libretranslate:5000/translate
```

Если настроены оба резерва, сначала используется собственный LibreTranslate,
а бесплатный Google — только когда LibreTranslate недоступен. Официальный
Google Cloud Translation тарифицируется отдельно и этим режимом не
используется.

### Альтернативы

`RUSSIAN_PROVIDER=claude`, `RUSSIAN_PROVIDER=deepl` или
`RUSSIAN_PROVIDER=libretranslate` в `.env`
переключают на дословный перевод вместо пересказа (код для этого тоже есть
в `src/russianVersion.js`) — но дословный перевод ближе к оригиналу
текстуально, а значит менее безопасен с точки зрения авторского права, чем
пересказ. `RUSSIAN_PROVIDER=mock` — тестовый режим без реальных вызовов API.


## Endpoints

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/news` | Вся лента. Параметры: `?category=Политика`, `?source=yle`, `?limit=50` |
| GET | `/api/news/sources` | Количество новостей по каждому источнику |
| POST | `/api/news/refresh` | Форсировать обновление; требует `Authorization: Bearer <REFRESH_TOKEN>` |

Редактор также может безопасно запустить обновление без копирования токена:
`/admin` → «Статьи» → «Обновить RSS сейчас». Кнопка получает только новые
материалы; уже сохранённые статьи повторно не переводятся.

## Безопасность API

Ручное обновление отключено, пока не задан `REFRESH_TOKEN`. После задания
токен передаётся только в заголовке `Authorization: Bearer <REFRESH_TOKEN>`.
Повторные ручные запуски ограничены `REFRESH_COOLDOWN_SECONDS` (по умолчанию
60 секунд). Плановое cron-обновление и обновление при старте не используют
токен.

CORS выключен по умолчанию. Если API нужен браузерному клиенту на другом
origin, явно перечислите разрешённые адреса в `CORS_ORIGIN` через запятую.

## Комментарии и модерация

Комментарии к статьям сохраняются со статусом `pending` и появляются
публично только после одобрения. Форма защищена honeypot-полем, ограничениями
длины и in-memory rate limit по IP (`COMMENT_RATE_LIMIT_WINDOW_SECONDS` и
`COMMENT_RATE_LIMIT_MAX`).

Форма связи защищена подписанным временем загрузки, скрытым honeypot-полем,
ограничением частоты по анонимному HMAC-идентификатору, лимитом ссылок и
подавлением одинаковых сообщений. Пороговые значения настраиваются через
`CONTACT_RATE_LIMIT_*`, `CONTACT_MIN_FILL_SECONDS`, `CONTACT_FORM_TTL_SECONDS`,
`CONTACT_DUPLICATE_WINDOW_HOURS` и `CONTACT_MAX_LINKS`. Исходные IP-адреса для
этой защиты не записываются в SQLite.

`/admin` рекомендует вход через Google OpenID Connect. Существующая пара
`ADMIN_USER` и `ADMIN_PASSWORD` продолжает работать только как аварийная
учётная запись администратора через HTTP Basic Auth.
Дополнительные отдельные учётные записи задаются секретом
`ADMIN_ACCOUNTS_JSON` в формате массива объектов `username`, `password`,
`role` (`admin` или `editor`). Если ни одной полной учётной записи нет,
модерация закрыта. Используйте Basic Auth только по HTTPS и с уникальными
сильными паролями. Все действия модерации требуют
`Origin`, точно совпадающий с `SITE_URL`; запросы без него или с чужого сайта
получают `403`. Для Coolify за одним reverse proxy установите `TRUST_PROXY=1`,
чтобы rate limit комментариев использовал IP клиента из `X-Forwarded-For`.
Вне доверенного reverse proxy оставьте эту настройку выключенной.

### Вход редакторов через Google

Рекомендуемый production-вход использует Google OpenID Connect. Он запрашивает
только `openid`, `email` и `profile`: сайт не получает пароль Gmail и не имеет
доступа к письмам. Сервер использует `state`, `nonce`, PKCE и официальную
`google-auth-library`, проверяет подпись и audience ID-токена, `email_verified`
и allowlist. OAuth state дополнительно привязан к одноразовой HttpOnly cookie
браузера. В SQLite хранится только SHA-256 случайного токена сессии; cookie
имеет `HttpOnly`, `SameSite=Lax` и `Secure` на HTTPS.

1. В Google Cloud создайте OAuth Client типа **Web application**.
2. Добавьте точный redirect URI
   `https://finskienovosti.fi/admin/auth/google/callback`
   и, если нужен вход через `www`, также
   `https://www.finskienovosti.fi/admin/auth/google/callback`.
3. В Coolify задайте `GOOGLE_OAUTH_CLIENT_ID`,
   `GOOGLE_OAUTH_CLIENT_SECRET` и `ADMIN_GOOGLE_ACCOUNTS_JSON`.
4. Оставьте старый `ADMIN_USER`/`ADMIN_PASSWORD` только как временный аварийный
   доступ и удалите его после приёмки Google-входа.

Сессия действует `ADMIN_SESSION_HOURS` часов. Входы, отклонённые аккаунты,
выходы и редакционные действия видны в журнале аудита.

Роли разделены по принципу минимальных прав:

| Действие | `editor` | `admin` |
|---|---:|---:|
| Создавать, импортировать, править и публиковать статьи | да | да |
| Модерировать комментарии и отправлять статью в Telegram | да | да |
| Смотреть статистику, CSV, повторы и журнал | да | да |
| Создавать, изменять и скрывать справочники контента | да | да |
| Удалять неиспользуемые записи справочников | нет | да |
| Безвозвратно удалять статью или комментарий | нет | да |

Запрещённая попытка редактора возвращает `403` и записывается в журнал как
`authorization.denied`. В production владельцу назначается `admin`, а всем
остальным сотрудникам — `editor`.

В админ-панели можно редактировать имя и текст любого комментария, менять его
статус, удалять комментарии, искать и редактировать статьи, создавать ручные
материалы, задавать срок закрепления и планировать публикацию на будущую дату.
Для ожидаемого финского времени задайте серверу `TZ=Europe/Helsinki`.
Автоматически пропущенный похожий материал можно проверить и опубликовать
кнопкой «Опубликовать всё равно». Статистика фильтруется по периоду до 90 дней,
категории и источнику; результат выгружается в CSV. Отдельный журнал действий
фиксирует учётную запись, действие, объект и время, но не хранит пароли или
полный текст материала.

Во вкладке **«Справочники»** редакция управляет категориями, тегами, регионами
и аудиториями. Запись можно создать, изменить или временно скрыть. Удаление
доступно только администратору и только если запись ещё не используется
статьями или пользовательскими подписками. Системные категории нельзя удалить,
а их постоянные имя и URL защищены от случайного изменения.

Новые RSS-, импортированные и ручные материалы автоматически классифицируются
по этим справочникам: получают категорию, регион, теги, аудитории и оценку
уверенности. Это локальная операция без дополнительного вызова AI. На странице
редактирования можно повторить классификацию одной статьи, а во вкладке
«Справочники» — пакетно обработать старые материалы. Slug и постоянная ссылка
при этом не меняются.

Во вкладке **«Качество»** находится очередь материалов, которые не прошли
автоматическую проверку. Для каждой статьи показываются важность от 1 до 5,
понятное объяснение классификатора, уверенность и точная причина сомнения:
например, отсутствие русского текста, тестовый перевод, слишком короткий
пересказ или низкая уверенность категории. Новые сомнительные RSS-материалы
остаются скрытыми черновиками. Редактор проверяет категорию и важность, после
чего явно публикует либо отклоняет статью; решение записывается в аудит.
Проверка выполняется локально и не расходует AI-токены.

Контроль качества не смешивается с редакционной публикацией: сомнительная
RSS-статья публикуется после одобрения, а импортированный или ручной черновик
после одобрения качества остаётся черновиком до отдельной команды
«Опубликовать». Повторно рассмотреть уже закрытую запись нельзя.

## Анонимная аналитика и срок хранения

Для дневной статистики просмотров и реакций сервер хранит только HMAC от
IP-адреса и User-Agent вместе с датой UTC; исходные IP и User-Agent в SQLite
не записываются. HMAC включает дату, поэтому один посетитель не получает
стабильный идентификатор между разными днями. Записи старше
`ANALYTICS_RETENTION_DAYS` (по умолчанию 90 дней) удаляются при старте и
ежедневно в 00:15 UTC. Перед публичным запуском опубликуйте политику
конфиденциальности, описывающую эту статистику и комментарии.

## Ручная отправка в Telegram

В `/admin` редактор может вручную отправить статью в Telegram. Для этого нужны
обе переменные: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Если хотя бы одна
не задана, отправка отключена и внешний запрос не выполняется. Используйте
`TELEGRAM_API_BASE_URL=https://api.telegram.org`; изменять его допускается
только для локального mock API при проверке. После успешной отправки статья
получает запись в журнале и повторная отправка кнопкой недоступна.

Отдельная вкладка `/admin?tab=telegram-channel` управляет общей публичной
лентой `@finskienovosti`: включение автопостинга, категории, важность,
минимальный интервал между сообщениями, дневной лимит, ссылки и HTML-шаблон
сообщения. Статьи, ожидающие окончания интервала, остаются в очереди и
проверяются каждую минуту. Там же есть безопасная тестовая отправка. Это
независимый сценарий: общий канал доступен всем читателям, а
персональная рассылка ниже отправляет выбранные новости в личный чат
конкретного пользователя.

Перед автоматической отправкой в общий канал статья получает прозрачный
рейтинг 0–100. Базу даёт редакционная важность 1–5; два независимых источника
добавляют 20 баллов, три — 30, четыре и более — 35. Дополнительно учитываются
метки «Важно»/«Срочно», прямая связь с Финляндией и свежесть. Повторы одного
источника не считаются подтверждением. Материалы на ручной проверке качества
или скрытые редактором не отправляются независимо от балла. Порог настраивается
в админке; значение по умолчанию 65. Чтения, реакции и комментарии намеренно не
влияют на первичный рейтинг, чтобы не создавать самоподдерживающийся рейтинг
популярности и не ставить новые события в заведомо худшее положение.

Общая публичная RSS 2.0-лента доступна по постоянному адресу
`https://finskienovosti.fi/rss.xml` (не более 50 последних опубликованных
русскоязычных материалов). Старый совместимый адрес `/feed.xml` перенаправляет
на `/rss.xml`. В RSS публикуются краткий русский пересказ и постоянная ссылка
на собственную страницу статьи, а не полный текст первоисточника.

Шаблон общего Telegram-канала по умолчанию использует безопасный HTML:
жирный заголовок, русский анонс до 280 символов, источник, категорию и ссылку
«Читать далее». Доступные подстановки:
`{label}`, `{category}`, `{source}`, `{title}`, `{excerpt}`, `{article_url}`,
`{original_url}`. В админке есть визуальный редактор, кнопки вставки
переменных, возврат к исходному красивому шаблону и безопасный предпросмотр
сообщения. Разрешены только поддерживаемые Telegram-теги и ссылки через
`{article_url}` или `{original_url}`; ошибочный шаблон не сохраняется. Данные
статьи HTML-экранируются перед отправкой.

Настройка канала:

1. Создайте бота командой `/newbot` у официального `@BotFather`.
2. Добавьте бота администратором Telegram-канала с правом публикации сообщений.
3. Для публичного канала используйте `TELEGRAM_CHAT_ID=@channel_username`; для
   закрытого канала нужен его числовой Bot API ID вида `-100…`.
4. Сохраните токен и Chat ID только как secrets в Coolify и выполните redeploy.
5. Для персональных подписок достаточно корректных `TELEGRAM_BOT_TOKEN` и
   `SITE_URL=https://...`: при каждом запуске сервер сам регистрирует webhook
   `https://YOUR_SITE/telegram/webhook`. `TELEGRAM_WEBHOOK_SECRET` можно задать
   явно, иначе безопасное значение вычисляется из токена бота.
6. В личном кабинете сайт автоматически определяет username бота методом
   `getMe`. Пользователь нажимает одну кнопку, попадает именно в нужного бота
   и подтверждает подключение кнопкой Start. Имя канала, Chat ID и код вручную
   вводить не нужно. При необходимости username можно задать явно через
   `TELEGRAM_BOT_USERNAME` без символа `@`.
7. При запуске сервер автоматически задаёт через Bot API русское описание и
   русское меню команд `/start`, `/settings`, `/help`. Эти настройки применяются
   как по умолчанию для всех пользователей, так и отдельно для языка `ru`.
   После `/start` бот отвечает на русском и даёт ссылку на личный кабинет.

### Персональная Telegram-рассылка

В `/account` пользователь входит через Google и подключает личный чат с ботом одной
кнопкой. После подтверждения `/start` рассылка включается автоматически. В кабинете
можно выбрать:

- мгновенную доставку или ежедневную подборку;
- категории и конкретные источники (YLE, Helsingin Sanomat и другие);
- только новости Финляндии или также мировые новости;
- период «Не беспокоить» по часовому поясу Финляндии;
- максимальное число сообщений в день и ссылки на первоисточники;
- «Слово дня», официальные и традиционные дни флага (`liputuspäivät`);
- праздники Финляндии (`juhlapäivät`), включая даты, зависящие от Пасхи.

Каждое сообщение содержит русский заголовок, краткое описание и постоянную ссылку
«Читать далее» на страницу статьи. Пропущенные из-за тихого времени или временной
ошибки свежие новости повторно проверяются каждые пять минут и не дублируются.
Ежедневные рубрики отправляются после первого выбранного времени доставки. Если
приложение перезапустилось позже, выпуск за текущий день будет доставлен после
запуска и не повторится благодаря отдельному журналу отправок в SQLite.
После подключения пользователь может нажать «Проверить доставку» в кабинете:
бот отправит одно явное тестовое сообщение только в его привязанный личный чат.

Публичная страница `/telegram` простыми словами объясняет преимущества,
настройки и три шага подключения. Ссылка на неё показана отдельным заметным
баннером под шапкой всех публичных страниц, а также добавлена в футер.

### SEO и постоянные страницы

Публичное название сайта в метаданных: «Финские Новости» с латинским вариантом
`Finskie Novosti` и ключевой тематикой «новости Финляндии». Каждая опубликованная
статья имеет постоянный адрес `/news/:slug`, canonical URL, метаданные Open Graph
и `NewsArticle` JSON-LD. Главная, архивы, категории, темы, регионы и статьи входят
в `/sitemap.xml`; черновики, поиск, админка и личный кабинет не индексируются.

Кнопка в `/admin` вызывает официальный метод Bot API `sendMessage`. Сообщение
содержит редакционную метку, русский заголовок, краткий текст и постоянную
ссылку на статью. Для персональных подписок статья уходит сразу после
публикации либо в ежедневной подборке — в зависимости от настроек пользователя.
Успех записывается по `message_id`, поэтому повторная ручная отправка этой
статьи блокируется.

## HTML-страницы

Сервер рендерит страницы напрямую из SQLite: `/` — 50 свежих новостей,
`/page/:number` — постоянные страницы архива по 50 материалов,
`/category/:slug` — категория, `/tag/:slug` — тема, `/region/:code` — регион,
`/search?q=...` — поиск по всему опубликованному архиву и `/news/:slug` —
постоянная страница отдельной новости. Укажите
публичный адрес сайта в `SITE_URL`, чтобы canonical URL был корректным.

Поиск учитывает текст статьи, категорию, управляемые теги и регионы. Для
поискового интерфейса доступен JSON endpoint
`/api/search/suggestions?q=...`, возвращающий до пяти опубликованных статей.
На странице материала показываются связанные, предыдущая и следующая новости.

Над AI-дайджестом главной страницы показывается бегущая строка последних
одобренных комментариев. Комментарии со статусом `pending` или `rejected` не
публикуются в этой строке.

## SEO

`/sitemap.xml` содержит главную страницу, страницы архива, категории, видимые
теги, регионы и все опубликованные статьи, включая материалы без даты
публикации.
`/robots.txt` разрешает индексацию HTML-страниц, запрещает `/api/` и содержит
абсолютный URL sitemap, построенный из `SITE_URL`.

## ⚠️ Важно: авторское право и юридическая сторона

Пересказ через ИИ (вместо дословного перевода) — более безопасный подход,
но не железная гарантия. Прежде чем публиковать такой сайт для широкой
аудитории, стоит понимать:

- Даже пересказ своими словами остаётся производным материалом от чужой
  новости. Это распространённая практика у нишевых агрегаторов, но
  **не автоматическое разрешение** на коммерческое использование в любом
  объёме.
- Обязательно держите на каждой карточке видимую ссылку на оригинал и
  название источника (в текущей вёрстке сайта это уже сделано) — читатель
  должен иметь возможность в один клик перейти к первоисточнику.
- Не пытайтесь через ИИ реконструировать полный текст платной статьи по
  крупицам — пересказ должен оставаться коротким тизером, а не заменой
  чтения оригинала.
- Если планируете расти и монетизировать проект — стоит списаться с
  редакциями (у YLE, например, есть открытые API для медиа-партнёров)
  и уточнить условия использования их RSS для агрегатора.
- robots.txt и Условия использования (Terms of Service) каждого сайта
  стоит проверить отдельно — RSS-фид, отданный публично, не всегда
  означает разрешение на любое переиспользование контента.

Это не юридическая консультация — при серьёзных амбициях по проекту
лучше свериться с юристом, знакомым с финским и европейским
законодательством об авторском праве (в т.ч. вопрос press publishers'
right в рамках копирайт-директивы ЕС, который прямо касается
агрегаторов новостей).

## Деплой

Используйте Node.js 20 или новее: это требуется текущей версией
`better-sqlite3`.

Для продакшена подойдёт любой Node.js хостинг с поддержкой
долгоживущих процессов и cron внутри процесса: Railway, Render,
Fly.io, обычный VPS с `pm2`. Serverless-платформы (Vercel Functions и
т.п.) не подойдут напрямую — там нет длительно живущего процесса для
`node-cron`, придётся выносить расписание во внешний cron-триггер.
